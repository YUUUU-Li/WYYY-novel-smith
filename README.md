# 吾又一言

长篇小说设定构思工作台。为「冰山在水面下的那部分」做的工具 —— 角色、地点、势力、事件、关系、地图、时间线、大纲、词条。

一句话说明它和 Word 的区别：**Word 帮你写字，这个工具帮你记住字背后的世界。**

## 启动（网页版 / 源码方式）

**双击 `启动.vbs`（推荐）。** 没有黑窗口：它在后台起服务器，然后开一个**应用窗口**（Edge/Chrome 的 app 模式 —— 没有地址栏、没有标签页，看起来就是普通软件的一个窗口）。

**要关掉，双击 `停止.vbs`。** 没有窗口可以点 ×，所以停服务器单独给你一个入口。它只会杀「在这个端口上监听、而且进程名是 node」的那个进程，不会误杀别的东西。关完窗口里会显示连接错误，直接关掉窗口即可。

> **为什么以前有个黑框：** 这是个网页程序，用的时候必须有一个本地服务器在跑，而 `.cmd` 是最透明的做法（能看到报错、点 × 就停）。现在把这一层藏起来了 —— 服务器照样在跑，只是没有窗口。

**`启动.cmd` 保留着，别删。** 它是「看得见」的版本：服务器起不来、端口被占、构建失败时，双击它能看到人话报错。`启动.vbs` 只是把它藏起来，出问题时还是得靠 `.cmd` 看日志。

**打不开网页时先看三件事：**

1. 服务器还在不在？`停止.vbs` 停过就是原因；重新双击 `启动.vbs`。
2. 双击 `启动.cmd`，看它最后一行写什么 —— 端口被占用、构建失败都会在那儿说明白。
3. 端口是不是被别的程序占了：默认 `5183`，可以用 `set PORT=5184` 再启动换一个（换端口等于换了一个存储空间，原来的书不会出现在新端口上）。

手动启动（需要 Node.js 20+，装了就能直接在终端里用 `node`）：

```powershell
cd novel-studio
npm install          # 第一次
npm run start        # 等就绪 → 开浏览器 → 起服务器
```

> Node 不在系统 PATH 里时，先把它加进来（路径换成你自己的）：
> `$env:PATH = "C:\Program Files\nodejs;" + $env:PATH`

然后打开终端里显示的地址（默认 http://127.0.0.1:5183/）。

第一次打开是一个空的作品库，直接输入小说名字、按回车就建好了。

### 常用命令

| 命令 | 作用 |
|---|---|
| `npm run start` | 起服务器并自动开浏览器（和双击 `启动.cmd` 等价）|
| `npm run dev` | 启动 Vite 开发服务器（改源码时用，带热更新）|
| `npm run check` | 类型检查 + 全部 657 项单元测试（改代码后该跑这个）|
| `npm run build` | 生产构建，产物在 `dist/` |
| `npm run serve` | 只用 `dist/` 起静态服务器，不开浏览器（127.0.0.1:5183）|
| `npm run icons` | 用内置图形重画全套图标，并同步网页 favicon |
| `npm run icons:from -- 你的图.png` | 用你自己的图生成全套图标（1024×1024 方图）|
| `npm run icons:web` | 只把图标同步成网页 favicon |
| `npm run verify:ui` | 在真实浏览器里核对界面（需要先 build + serve）|
| `npm run verify:map` | 在真实浏览器里核对地图 |
| `npm run verify:org` | 在真实浏览器里按住卡片拖动，核对换位、放进夹子、面包屑移出、嵌套 |
| `npm run verify:layout` | 在真实浏览器里量各层高度，验证滚动 |
| `npm run verify:terms` | 拿一份「旧格式」作品核对字典合并、断链、迁移落盘 |
| `npm run check:publish` | 发行前自查：全仓找本机路径、邮箱、凭据；可以跟词，查你小说里的专有名词有没有漏进代码里 |

> `启动.cmd` 里**一个中文字都不能有**。cmd.exe 在代码页切到 UTF-8 之后读批处理会按字节算偏移，行里带中文就可能串位，然后把半个汉字当成命令去执行（`'ho' is not recognized as ...`）—— 表现就是双击了没反应、窗口一闪而过。所以 `启动.cmd` 和 `安装Rust.cmd` 都是纯 ASCII 的，中文提示全部交给 `scripts/` 下的 Node 脚本打印。

## 换图标

两处图标来自**同一张源图**，别分开改：

| 露在哪 | 文件 | 谁读它 |
|---|---|---|
| 浏览器标签页 | `public/favicon.ico`、`public/favicon.png` | `index.html` |
| 桌面快捷方式、exe | `src-tauri/icons/icon.ico` | Windows |

### 换成你自己的图

**图标源是仓库根目录的 `logo.png`。** 改它，然后：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\make-icons-from-logo.ps1
npm run icons:web                   # 同步成 favicon
# 把 index.html 里 favicon 链接的 ?v= 数字加一（浏览器按 URL 缓存图标）
npm run build                       # 让 favicon 进 dist/
```

那个脚本的做法：每一档都从原图单独渲染（不让图标经过中间尺寸反复重采样），小尺寸再做一次对比拉伸，让笔画保持实心而不是灰雾，最后按 ICO 规范手工拼出 7 档的 `icon.ico`。

> `npm run icons` 画的是早期那版「夜蓝 + 三行刻痕」的程序化图形，现在会检测到 `logo.png` 存在并直接退出，不会覆盖。
>
> **网页用的 favicon 是单独一份**：它来自 `logo2.jpg`（573×534，边缘比 `logo.png` 干净），
> 由 `scripts/make-favicon.ps1` 生成到 `public/`。所以**别用 `npm run icons:web` 覆盖它** ——
> 那个命令会把 `src-tauri/icons` 里的桌面图标复制成 favicon，正好把这份盖掉。

**快捷方式不用重建。** 它存的是 `src-tauri/icons/icon.ico` 这个路径，文件内容一换，图标就跟着换。
如果资源管理器还顽固地显示旧图标，那是 Windows 的图标缓存 —— 把快捷方式删掉重建一个，或者注销一次就干净了。

### 只换网页那个

直接把 `public/favicon.png` 换成你的 128×128 PNG，然后 `npm run build`。桌面图标不动。

### 用回内置图形

```powershell
npm run icons
```

内置图形画在 `scripts/make-icons.mjs` 里（圆角深底 + 三行刻痕，末行琥珀收尾）。想微调配色和比例，改文件开头那几个常量即可，不需要任何外部素材或依赖。

## 界面速览

| 视图 | 回答什么问题 |
|---|---|
| **概览** | 我这部小说的整体状态？哪里还没填？ |
| **设定** | 这个角色/地点/事件是什么？它和谁有关？ |
| **手绘** | 自己摆一张关系图：拖词条进来、连线、选线头与线型 |
| **时间线** | 自己摆的时间线（竖排、可对齐）· 另有事件轴（先后）· 轨道（各地同时发生什么）· **在场（谁在何时何地）** |
| **地图** | 几张图（世界总图 / 街区图 / 行军路线），每张自己钉图钉、圈区域 |
| **大纲** | 卷→章→场景的结构、剧情线走向、谁被冷落了？ |
| **字典**（已并入「概念」）| 自造词、术语、行话 —— 就是概念条目；读音/直译是它们的自定义字段 |

> **「字典」这一栏已经删掉，并进了设定。** 词条和条目几乎是同一个东西（名字、说明、正文、关系、搜索），分开存必然出矛盾：`[[息]]` 的跳转只认条目，而字典把「息」算作已解释 —— 警告没了，链接还是死的。现在：
>
> - 每个词就是一条**概念**条目（一个 `.md` 文件），读音/直译是概念类型的两个自定义字段
> - 「哪些词被引用但还没解释」升级成了**断链检查**，放在概览的「要处理的」里：`[[雪原]]` 解析不到就列出来，一键「建成条目」。这条对角色、地点、事件全都成立，不再只管自造词
> - 概览底部多了一张**只读的术语表**（概念条目按读音排，可复制成 Markdown 当读者词表）—— 它是视图，不是存词的地方
> - 打开旧作品时会**自动迁移**一次：每个词变成概念条目，同名的并进已有条目，然后顺手落盘，`词条.json` 变成空数组

### 设定页：拖动排位 + 词条夹

设定页有两种排版，**两种都能拖**：

- 卡片网格（默认）：有呼吸感，材料看得全
- 紧凑表格：条目多时用来扫视

**按住任意一张卡片拖动就能换位置**，像 PPT 里挪幻灯片一样：**两条之间的那条红线**就是它会插进去的位置。手写顺序存在 `novel.json` 里，不是算出来的。

> 排序下拉里有「按名称 / 按关系数 / 按时间」。这些顺序是算出来的，拖动没有意义，
> 所以**一拖就自动切到「手动顺序」** —— 不这么做的话，松手瞬间会被重新排回去，
> 看起来像「拖了没用」。

**同一个条目可以摆在好几个夹子里。** 「齐国伐宋」既是齐国的事，也是宋国的事 —— 打开那个条目，在左边的**摆放**里把两个夹子都勾上，它就在两个夹子里各露一头。

这不是克隆，也刻意没做成克隆：**放的是位置，不是数据**。名字、正文、关系、出现过的场合全都只有一份，所以在哪个夹子里点开都是同一条，改一次两边一起变。克隆出第二份数据就必然要同步，而同步迟早会漏一边 —— 这条需求真正的难点不在「复制」，在「永远一样」，而那只有一个做法：不复制。

- 摆放列表里勾上的夹子再点一下 = 把那处**撤掉**，条目本身不受影响
- 拖动一张卡片只搬**这一份**：在宋国里把它拖出去，齐国里那份还在
- 词条夹不能这样放（子树会被数两遍），列表里也不会出现它

**词条夹**（右上角「新建词条夹」）像文件夹一样用：

- 点进去 = 进入夹子页面。页面和顶层几乎一样，**顶上多一块写夹子名字和简介的地方**
- 夹子自己也能拖，**也能拖进别的夹子里**（想套几层套几层）
- **指针进到词条夹的框里就够了** —— 整个框都是落点，框会整块变成朱砂色，松手收进去
- 想拿出来：进夹子，把条目拖到**面包屑**上任意一级
- **解散夹子不会删里面的东西**，它们留在原来那一层。这是这类工具最不能犯的错

**夹子上的数字是「继承」的**：一个夹子显示的是**它自己 + 所有子孙夹子**里的条目数，**词条夹本身不算条目**。所以宋国里放 4 条、再建一个空子夹，宋国还是显示 4；往子夹里加 2 条，子夹显示 2、宋国显示 6。

> 数字对不上时先看括号：夹子里还有夹子时，显示会写成 **「7 条（自己 4）」**—— 前一个是继承来的总数，后一个是直接装在它里面的。没有括号就说明两者相等。

> 同一个页面上还有另一个数字：筛选栏左上角的「全部 N」。**那个数的是这一层直接装着的条目**（筛选器筛的就是这些），进了夹子它就只数夹子里的。两个数字回答不同的问题：夹子上的「多少东西在这个夹子里」，筛选栏的「这页有几行」。

> 左边那栏（搜索 + 词条速览）**默认收起**，一打开先让列表和正文占满宽度；点最左边那个图标展开。

三条判定规则，说的话就是代码在做的事：

| 指针在哪 | 判定 | 看到什么 |
|---|---|---|
| 面包屑的某一级上 | 放进那一级 | 那一级变成朱砂虚线框 |
| **词条夹的框里**（整个框） | 放进这个夹子 | **整个框变成朱砂色** |
| 别的地方 | 换位 | 两条之间一条**红线** |

刻意**不**做的事：不给「放进这个夹子」那种小徽标。徽标太小、还得挂在卡片里，同级条目会被误挂上，等于把「哪个才是能放进去的目标」这件事搞乱了 —— 框本身就是目标。

还有一条看不见但很要命的：**拖动词条板关掉了文本选择**。不关的话，在卡片名字上按下再移动会被浏览器判定成「选择文字」，拖动变成拖蓝、卡片不动，而且必须先点空白处取消选中才能再拖。画布那边（`CanvasGraph`）踩过同一个坑，两处都关掉了。

背后三条实现上的取舍：

- **拖动时拍一张位置快照，整场拖动只看它。** 一边重排一边按当前位置算落点会自己喂自己 —— 指针不动也可能来回跳。
- **面包屑栏必须常驻。** 它原来只在拖动时出现，结果一动鼠标它就把整个列表往下推 30 多像素 —— 而落点判定用的是「按下那一刻」的位置快照。列表在手指底下自己挪了位置，红线自然画错、东西也就落错格。
- **落点 index 不能直接套到底层数组上。** index 是相对**屏幕上那一列**算的，但顺序存在另一份数组里；类型筛选会藏起条目，非手动排序又是另一个排法。所以换位走 `reorderVisible`：只把看得见的那几个槽位重排，看不见的原地不动。为此「手动顺序」下界面**原样**用存下来的顺序，一个字都不重排 —— 只要这里偷偷把夹子提到前面，index 就会落到别人身上。
- **表格的行之间留了 3px 真实的缝**，否则「整框 = 放进」会把两个夹子之间换位的位置全吃掉。

### 时间线：先选一张，再进去摆

点「时间线」看到的是**你建的时间线列表**（每张写着名字和整体时间跨度），点进去才是那张图。

图是**竖的**：时间从上往下走，滚轮上下看。左边是所有事件条目，**把它拖到右边**——不用管拖到哪儿，它会自己排到对应的时间行上：

- **一行 = 一个具体时间**（纪元+年+月+日，你写到哪一级就算到哪一级）。同一天发生的事落在同一行，所以「同行 = 同时间」是成立的，不是摆出来的
- **左边的刻度**上排写到年（公元纪年写成「前293 年」这种，不是一个光秃秃的数字），下排写月日。同一年里不同月份的几件事，靠下排分辨
- **左右位置是自己摆的**，按住格子横着拖。同一行里一左一右，就是「同一时间、两个地方」
- **板宽**（顶上那个 ×1 / − / +）：同一时间的事一多，一行就摆不下了。点 + 把画布放宽到 1.5、2、3 屏……，右边会出**横向滚动条**，滚轮 + Shift 也能左右滑。**放宽只是把画布放大**，格子的相对位置一个都不动（存的是 0~1 的百分比，不是像素）
- **滚到右边时，左边的刻度不会跟着跑**：它钉在左边，所以横着滑几屏都还知道自己在看哪一年
- **鼠标停在格子上**会浮出这件事的**时间、地点、参与角色**（还有「后果」），和「全部事件」那张自动排好的图是同一套取值 —— 两处不会说法不一
- **列 = 一条带名字的竖线**，点「加一列」会在板子顶上长出一个列表头，你给它起名（齐国、宋国、某个战场、某条人物线都行），按住表头左边的 ⠿ 能左右挪它。**它只是对齐用的参照，不会把格子锁死在列上** —— 第一次加列时会当场解释一遍
- 没填时间的事件拖进去会先落在上面的**「未定时间」**里（不会丢）；给它填个年份，它自己会落到对应那一行
- 格子右上角的 × 只是**从这张时间线上拿掉**，条目本身一直在
- **名字就在顶上改**：点那行标题直接打字，不用翻回列表

> **行不能拖，只有横坐标能拖，这是刻意的。** 行是事实（这件事发生在哪一年），要改它只能去改事件的时间；横坐标是判断（这件事画在左边还是右边），只有它需要人来做。两者都能拖，就会出现「第 3 行的事件」和它的时间对不上的状态。

列表最下面还有一条固定的入口：**「全部事件：自动排好的事件轴 / 轨道 / 在场」**。那三种是*算出来*的（所有带时间的事件按先后铺开，不用你摆），回答的是另一个问题。手工摆的时间线是*挑一部分、摆成一张图*，和它并存。

### 全部事件：事件一多，靠「时间窗」而不是靠叠楼

这三张是**只读**的：位置由数据算出来，你摆不动它 —— 这是它值钱的地方，它永远不会和你的数据说法不一。代价是它不像手工板那样能「腾地方」，于是密度只能靠视野控制：

- **在刻度条上按住拖一段 = 只看那一段**。轴会重算，叠行立刻降下来；顶上的标签写着「421 – 422 · 4 / 12 件」，剩下的去哪了也说得清
- **点一下刻度条 = 回到全部**（拖出的距离不到整段的 1.5% 就算「点了一下」）
- 第一次进来的解释条可以关掉；它不会在你拖完的瞬间自己消失 —— 那会让整块画布突然上移三十像素，而你的手还按在原地
- 选框和刻度用**同一个坐标**：拖出来的必须是你眼睛看到的那一段，两套坐标差一点，框住的就是别的东西
- 缩放（×1–×12）和时间窗是两件事：缩放只是把同一段画宽，时间窗才是换一段

> 上千个事件的规模没做虚拟化 —— 行数和格子数就是 DOM 节点数。一两百个事件时它够用；真到那个量级，该做的是虚拟化和默认折叠，那是另一件事。

### 手绘图谱怎么用

1. 左边是按类型分组的词条，**拖进右边画布就生成一个方格**
2. 方格可以用鼠标拖动摆位（位置会存进条目数据，关掉重开还在）
3. 点方格 → 左栏显示这个词条的设定速览
4. 切到**「连线」**，点起点方格、再点终点方格，建立关系。旁边两个下拉分别是**线头**（无线头/单向/双向）和**线型**（实线/虚线）
5. 切到**「删除方格」**点一个方格 → 它连同它所有的线一起移除（条目本身还在，只是不在图上）
6. 切到**「删除连线」**点一条线 → 只删那一条关系
7. 误删了按**「撤销」**

两个方格之间可以有多条线（比如方向相反的两个单向箭头），它们会自动散开成曲线，不会重叠。**进入视图时默认是「选定」模式**，不会误删或误连。

### 地图怎么用

点「地图」先看到的是**地图列表**（缩略图、图钉数、区域数、有没有底图），点一张才进那张图；顶上的名字**点进去就能改**，左上角的箭头退回列表。一部长篇往往不止一张图 —— 世界总图、某座城的街区图、一条行军路线，各建一张，「新建地图」在列表右上角。

> 这一层是补上的：以前「新建地图」只出现在**一张都没有**的时候，建完第一张，界面上就再没有地方能加第二张了。数据本来就已经是多张的（`WorldMap[]`，每张自己带 id、名字、图钉、区域、底图），缺的只是这层入口。

1. 点**「底图」**传一张图（手绘扫描、AI 生成、网上找的都行）。不传也能用，会画一张程序生成的经纬底纹
2. **「平移」**拖动、滚轮缩放；**「适应窗口」**把地图缩到正好放得下并居中
3. 切到**「打点」**，在地图上点一下就是一枚图钉，再在右侧选它代表哪个条目。图钉可以**自己起名字**，也**可以自己挑颜色**（不挑就跟着条目类型走，一眼能看出是角色还是地点）
4. 切到**「圈区域」**连点几下围出一块地，三个点以后**「封口成区域」**。每个区域可以**改名、挑颜色、写一段简介**
5. **图钉随时能拖。** 在「平移」或「打点」模式下按住图钉就能挪它 —— 平移模式下按住的若不是图钉，才是拖动整张地图
6. 每张地图的图钉和区域**只属于它自己**：新开一张图是干净的，不会带着上一张的点

**多张地图之后，「发生地点」的候选是跨图合并的。** 两张图上都有「北境行省」时，下拉里会把所属地图写在名字旁边当提示，而不是替你猜一个；自己打字且同名不唯一时，就老老实实留成文字。

**右侧清单平时只露名字。** 每张卡片收起时只有一行名字，点一下才展开出条目、名称、颜色和简介 —— 图多了以后，一屏能看全所有图钉和区域，而不是被一堆色板和输入框淹掉。收起时显示的名字就是你给它起的那个。

**每个方格用自己在地图上的那个颜色染一遍**（底色掺一点、边框掺得多一点），所以收起状态下不用额外的色点，扫一眼方格的颜色就知道它对应地图上哪一块。没挑过颜色的区域是中性墨色，不会凭空被染成某个色。

**颜色一共十二个**，从墨、玄、灰三个中性色排到暖色、绿、冷色，扫过去是一条光谱。它们和手绘图谱的连线用同一套色板，所以「朱砂」在哪里都是同一个朱砂。挑色的硬约束是**任意两色都得肉眼分得开**——测试里真的在量两两 RGB 距离，不许出现「两个看着一样的色」这种废选项。

右侧「区域」标题旁边有个**「上色」开关，默认开**：开着时每个区域在地图上显示自己的颜色，关掉就全部退回墨色轮廓（形状还留着，方便看清底图本身）。这个开关是**存在地图数据里**的，关掉之后重开还是关的。

三个工具按键的选中态是**朱砂字 + 朱砂下划线**，不是方框 —— 和顶部导航同一套语言。

图钉和区域的坐标存的是 **0~1 的归一化比例**，参照物是**地图自己的平面**（按底图宽高比铺开），不是画布。所以窗口怎么改大小、侧栏怎么伸缩，图钉都不会从它盯着的那个地方溜走；将来换一张更高清的同一张地图，也依然钉在原地。

> 底图会被压到 2048px 长边以内再存进小说文件 —— 浏览器本地存储只有几 MB，
> 原图直接塞进去会让保存失败。压缩了会在提示条里明说，不会偷偷动你的图。

## 数据存在哪

### 选文件夹之前：暂存在程序内部

不选文件夹时，数据存在程序自己的本地存储里（浏览器形态是浏览器的 local storage，桌面形态是它自己的界面内核）。关掉不会丢，**但你看不到文件**，也拷不走，换一台机器就带不过去。

一处要留意的差别：**浏览器版和桌面版是两套内部存储**，即使地址看起来一样也不互通。想在两边之间搬，就选同一个小说库文件夹 —— 文件是两边都能读的。

### 推荐：你自己的文件夹（纯文本优先）

在**作品库**页面点「选择小说库文件夹」：

- **桌面版**弹出的是 Windows 自带的选文件夹窗口，选完就是真实路径，**下次启动自动接着用**，不会再问你。
- **浏览器版**用的是 Edge/Chrome 的文件夹授权。浏览器规定页面不能自己重新打开上次的文件夹，所以每次启动要多点一下「继续使用」——这是浏览器的安全边界，不是偷懒。

之后：

> **这个仓库里不含任何作品内容。** 代码是代码，小说是小说：
> 工具本身没有内置示例小说，你的稿子在你选的那个文件夹里（或者浏览器里）。
> 想确认没有人把自己的东西写进代码里，跑 `npm run check:publish` ——
> 它会扫全仓，找本机路径、邮箱、凭据，也可以把你小说里的专有名词当参数传进去查：
> `npm run check:publish -- 战国记 云京`。
> 唯一的规矩：**别把小说库文件夹指到这个仓库里面。**

```
你的小说库/
└── 小说/
    └── 书名/
        ├── novel.json             历法、关系词表、地图与图钉
        ├── 角色/
        │   ├── 林昭.md            一个角色一个文件
        │   └── 苏无咎.md
        ├── 地点/北境要塞.md
        ├── 事件/北境要塞陷落.md
        ├── 势力/北境军团.md
        ├── 物品/寒刃.md
        ├── 概念/冰息.md
        ├── 大纲.json
        ├── 词条.json
        └── 历史/                  每次保存留一份快照（保留最近 60 份）
```

实体文件的格式是 **YAML front matter + Markdown 正文**：

```markdown
---
id: char_linzhao
type: character
name: 林昭
tags: [主角, 军人]
summary: 北境要塞守将。
status: 存活
at: loc_beijing
date: { year: 312, era: '天和', month: '霜月', day: 12 }
fields:
  能力: 寒刃。能在三息内冻结半径十丈的水汽。
links:
  - { to: char_suwujiu, type: 敌对, weight: 5, note: 十年前那场审判的当事人 }
---

## 来历
出身北境猎户，十七岁那年亲手烧了自家的粮仓。
```

这意味着：**能用记事本直接改、能丢进 Git 逐行 diff、能整包拷走、程序没了数据还在。**

### 程序能发现你在外部改了文件

文件夹模式下，程序每 5 秒检查一次。如果你在记事本里改了 `林昭.md` 并保存，程序会弹出提示，让你选：

- **载入磁盘版本** — 以你手改的为准
- **保留当前版本** — 以程序内存里的为准，写回磁盘
- **稍后再说** — 知道了，但下次自动保存仍会覆盖磁盘

**为什么不做自动合并**：一次错误的自动合并会毁掉设定，而多问一句的成本只是点一下。

## 几个不太显眼但值得知道的设计

**保存失败会明确告诉你。** 顶栏右侧一直显示保存状态：`已保存` / `保存中…` / `有未保存的改动`。如果写盘失败（磁盘满、浏览器收回文件夹权限、文件夹被移走），会变成红色的具体原因并带一个「重试」按钮——**不会静默失败**。对「文件即真相」的工具来说，这是最不能被容忍的问题：数据没存上而你不知道。

**关系仍然只写一遍，但不再在条目页里手动编。** 条目编辑器里那一块「指向别人 / 被别人指向」已经拿掉了 —— 它占着正文上面半屏，而真正每天用的是正文。现在关系只有两个入口：**手绘图谱连线**，和**事件里的「参与角色」**。数据模型没变，仍然是一条边只写一次，另一侧自动能看到反向记录。

**事件有「参与角色」这一栏。** 谁在这场戏里，在事件条目上直接选（也可以当场写个没建过的名字，会立刻建成角色条目再连上）。它写进去的就是一条 `参与` 关系，所以在场矩阵、时间线、手绘图谱读到的都是同一份东西。以前只能绕到「关系」里手打一个「参与」关系类型，没人找得到 —— 时间线的浮层于是老写着「还没有参与角色」。

**正文里写 `[[苏无咎]]` 就能跳转。** 鼠标放到那个名字上会转成朱砂、光标变手型，点一下就跳到那个条目 —— **就在正文编辑器里，不用切什么预览模式**。跳转目标不能在正文里点进光标中间（用方向键可以），因为一下点就是「跳走」。

写错了（指向不存在的条目）会变成灰虚线，点它不跳转 —— 那是写作时的待办，不是错误。等你真去建了那个条目，它会自己变回朱砂链接，不用重新编辑这一行。

**「被提及」不需要专门一栏。** 全书任何一处提到这个名字，全文搜索都能找到，并给出上下文片段。比如搜「林昭」，会看到苏无咎的关系备注里提到他、云绮的动机字段里提到他、寒刃的来历里提到他。这是核对一致性的入口。

**在场矩阵能抓出剧情矛盾。** 时间线 → 在场：如果两个宿敌被安排在同一年同一地，而剧情从没交代过，右侧会给出「关系冲突」提示。如果两人同处一地却没有任何关系记录，会提示这是「一场被漏掉的戏」。

**角色的位置由「参与了哪个事件」推出来。** 事件条目上有一个「发生地点」，谁参与了它，那一年就算谁在那儿。不需要另外维护一份「这个角色现在住哪」——那种字段会过期，也会和事件里的说法打架。**所以角色的编辑器里没有「所在地点」，也没有「驻留历史」。**（老文件里如果手写了 `at:`，在场矩阵仍然认它。）

**没有「别名」这一栏。** 同一个人的其他叫法（小名、绰号、封号）直接写进「一句话」里就行——反正搜索扫的是正文和字段，找得到。

**虚构历法。** 日期不是 JavaScript 的 Date，而是结构化的「纪元/年/月/日」，月份名可以是「霜月」「雁月」。跨纪元排序、时间线刻度都正确。

**单一强调色 + 每组实体固定色相。** 界面是「案头宣纸」：米白纸底、墨色文字，一个朱砂强调色（`#9c3f30`）。界面用宋体统一，设定正文也用宋体，所以设定读起来像稿纸。分层只用线，不用阴影。

**悬停一律是朱砂，不是墨。** 全站只有一个 `--color-hover`（淡朱砂 11%），凡是「鼠标放上去有反应」的地方都用它：次按钮的底、导航与工具标签的字、输入框的描边、列表行的底、卡片的底与描边。

> 原来次按钮悬停是**填成墨色**（近黑）——那不是这套纸面语言里的颜色，纸面上「有反应」就该是印泥红。想调深浅只改这一个 token。

**圆角统一从 token 取。** 形状分四档，别在组件里写死 px：

| token | 值 | 用在哪 |
|---|---|---|
| `--radius-xs` | 3px | 类型圆点、色块这类 10px 上下的小方块 |
| `--radius-sm` | 6px | 标签、行内小块 |
| `--radius-md` | 9px | 按钮、输入框、紧凑表格的每一行 |
| `--radius-lg` | 13px | 面板、卡片 |
| `--radius-xl` | 18px | 整块浮层（搜索面板）|

两处不是改 token 就完事的：

- **手绘的方格**是 SVG `<rect>`，圆角得配 `clipPath` —— 左边那条类型色带是另一个 rect，直接给主体加 `rx` 的话色带会在圆角处戳出来。
- **紧凑表格**原来是通栏横线，和圆角语言不搭。现在每行是一块圆角小条，底色画在单元格上、只给首尾两格加圆角（`.ns-rows`）；行间那 3px 的缝还在，拖动的换位落点才落得进去。
- **设定页卡片**的悬停与「放进夹子」高亮原来写在行内样式里（还配了 JS 的 `onMouseEnter` 改边框色）——行内样式优先级比 `:hover` 高，CSS 里怎么写都盖不住。搬进 `.ns-card` 之后顺序才有意义：拖动时的高亮压在 `:hover` 之后，不会被悬停盖掉。

### 桌面版启动：踩过的坑（已修）

release 版曾经一启动就以 `0xC0000409` 一声不响地退出。真相不是"栈溢出"：**WebView2 打不开它的用户数据目录**（被上一次没退干净的 `msedgewebview2.exe` 占着 → `ERROR_BUSY 0x800700AA`；没有写权限时是 `os error 5`），Tauri 建窗口失败后 panic，而 release 档是 `panic = "abort"`，abort 在 Windows 上表现成 `0xC0000409`。

现在的处置（`src-tauri/src/lib.rs`）：

1. **窗口改在代码里建**（`tauri.conf.json` 的 `windows` 是空的），这样才能给 WebView2 指定缓存目录。
2. **启动先探测默认缓存目录能不能用** —— 用"改名"来判断（目录里有进程打开着文件就不许改名）。被占就自动换一个 `EBWebView-<时间戳>`，并在 `crash.log` 里记一笔；顺手清掉以前留下的临时目录。
3. **单实例**（命名互斥体 + `FindWindowW`）：第二次双击只把已有窗口恢复到前面，不会再开第二个进程去抢同一个目录。
4. **崩溃可见**：panic hook 写 `%LOCALAPPDATA%\com.novelstudio.desktop\crash.log` 并弹消息框。

> **给以后调试的自己**：这个应用**不能在受限沙箱里启动**（比如只允许写工作区的环境）。WebView2 要往 `%LOCALAPPDATA%` 写缓存，被拦下来就会报 0x800700AA / os error 5，看起来像"程序一启动就崩"，其实是环境问题。本次就为此误判过一轮。

## 已知的改进空间

- 前端包 1.1 MB（gzip 350 KB）。CodeMirror 可以按视图懒加载，但桌面工具下首次加载不到一秒，收益有限。
- **底图目前是当作 dataURL 存进 `novel.json` 的。** 上传时压到 2048px 以内，所以一张大图会让 `novel.json` 多出约 1 MB，而且这份文件不再是人能读的纯文本。正道是把底图写成小说文件夹里的一个真图片文件（`地图/xxx.png`），`novel.json` 里只留路径 —— 那样还能直接换成更高清的版本。这一步要动磁盘格式契约（Rust 侧按同一份契约实现），所以留着单独做。
- 大纲的拖拽只支持同级重排，不支持跨层级拖动。
- **在场矩阵现在完全由「事件 + 发生地点 + 参与」驱动。** 一个从不参与任何事件的角色，在矩阵里就没有位置，只会出现在「缺地点」那一列里。这是删掉角色的「所在地点」之后必然的结果 —— 如果你后来觉得这个视图没什么用，可以整个去掉。
